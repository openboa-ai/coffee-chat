# First Loop & MVP Acceptance Specification

**Status:** Active MVP acceptance contract — expanded for the Coffee Chat UX/IA & spec redesign (2026-11-24). Governs verification in `packages/core`, `apps/web`, `packages/mcp-apps`, `evals/`, and `e2e/`.

## Goal

Prove the complete Coffee Chat loop end to end against a real Postgres engine (PGlite locally, Neon-compatible schema), live/deterministic authentication, Zero-AI `@openboa/yogurt` web service (personal workflow, sharing tables, deterministic insights), OAuth 2.1 MCP Server + 3 MCP Apps, and independent Taste evaluation harness.

## Observable Acceptance Criteria

### A. Core Domain, Privacy, Concurrency & Deterministic Insights (PGlite / Postgres)
1. **Default Private & Exact Digest:** Calling `prepareBean` for both `source_excerpt` and `work_episode` (including multi-origin payloads of 2–8 origins) returns `visibility: "private"`, normalized origins, RFC 8785 JCS SHA-256 `digest`, and `operationKey` without writing to DB. Calling `saveBean` with a tampered payload or mismatched `digest` fails (`400 DIGEST_MISMATCH`); calling with matching `digest` persists revision 1, version 1.
2. **Idempotency & Non-Resurrection:** Replaying `saveBean` with the same `(ownerId, operationKey, requestDigest)` returns the original Bean without duplicating rows; reusing `operationKey` with a different payload fails (`409 IDEMPOTENCY_CONFLICT`); deleting a Bean removes content/revisions while retaining a content-free receipt so replaying the prior write fails and never resurrects the Bean.
3. **Optimistic Concurrency:** Editing content or switching visibility increments `version`; a stale mutation carrying the previous `expectedVersion` fails (`409 VERSION_CONFLICT`) with latest version metadata and cannot overwrite or re-publish the Bean.
4. **Aggregate Count Exposure vs Zero Leakage:** A user with 1 `public` Bean and 1 `private` Bean (plus a `refines` relation between them, private tags, and a private-only URL origin) exposes `publicCount: 1, privateCount: 1` publicly (`getPersonProfile(..., viewerId = null)`), while non-owners receive `404` on the private Bean ID, `404` on the private-only URL in `getSourceCompare`, zero private origins/tags/timestamps, and zero relation edges referencing the private Bean.
5. **Work Episode Public Redaction Guard:** Switching a `work_episode` Bean from `private` to `public` via `saveBean` or `setBeanVisibility` fails (`400 REDACTION_REQUIRED`) unless `redactionConfirmed: true` is explicitly passed.
6. **Living Taste Relations & Live Shelf:** `supersedes`, `refines`, and `tensions_with` persist with same-owner and `supersedes` acyclicity checks; Shelf saves a public Bean or `@handle` by live reference only and immediately stops returning it once the owner switches it to `private` or deletes it.
7. **Deterministic Insights & Zero-Leakage Aggregation:** `getPersonalInsights(db, ownerId)` returns exact SQL/TS counts matching DB state (`totalCount`, `publicCount`, `privateCount`, `originMix` presence counts, `captureMix`, mutually exclusive `lifecycle` summing to `totalCount`, `revisionCount`, `relationCounts`, `topTags`, `activeGrantCount`, live-resolved `shelfCount`). Non-owner `listBeans` / `listBeansPage` `lifecycleState` filters inspect only `bean_relations` where both endpoints are `public`; `getViewerStanceForOrigin` returns `null` on empty/null `viewerId`; public aggregates on `/@[handle]` and `/sources/[id]` match `visibility = 'public'` rows exclusively and never include private tags, private origin kinds, or private relation edges.

### B. OAuth 2.1 MCP & MCP Apps End-to-End
8. **Discovery & PKCE Flow:** Unauthenticated `/api/mcp` returns `401` with RFC 9728 `WWW-Authenticate` header. A real OAuth 2.1 client completes discovery (`/.well-known/*`), DCR or SSRF-guarded CIMD registration, Authorization Code + PKCE (`S256`) via `/oauth/consent`, receives opaque access & refresh tokens, and calls `get_profile`, `prepare_bean`, `save_bean`, `list_beans`, `get_bean`, `manage_shelf`, and `compare_perspectives`.
9. **Instant Revocation:** Revoking the grant via Web (`/me?tab=settings`) or `/api/grants/[id]/revoke` immediately rejects both subsequent `/api/mcp` calls with the old access token (`401`) and token refresh requests with the old refresh token. Re-consenting issues a new `grantId` and never revives previously revoked tokens.
10. **MCP Apps Resources & CLI Fallbacks:** All 3 `ui://coffee-chat/*.html` resources serve valid self-contained `text/html;profile=mcp-app` bundles under 10 MiB with zero external `<script src>` or `<link rel="stylesheet">`; every tool returns both `content` (CLI Markdown fallback) and `structuredContent`.

### C. Auth, Zero-AI Web Service & `@openboa/yogurt` Compliance (Playwright + `yogurt check`)
11. **Live Better Auth & Deterministic Test-Auth Gates:**
    - *Automated CI / Local E2E (`COFFEE_CHAT_ENABLE_TEST_AUTH=true`):* Unauthenticated navigation to `/me` or `/oauth/consent` redirects to `/signin?returnTo=...` and returns to validated same-origin `returnTo` after login (rejecting protocol-relative `//evil.com` or `\` payloads); `/api/test-auth/login` authenticates preset or custom users; `/api/test-auth/logout` clears the session; production builds (`NODE_ENV=production`) reject both `/api/test-auth/login` and unverified JSON `POST /api/accounts`.
    - *Explicit Provider Linking & Unlink Guard:* `/me?tab=settings` displays linked providers, renders GitHub/Google explicit link actions (`/api/auth/link-social` in live Better Auth; `test-auth`-gated `POST /api/accounts` in local E2E), rejects linking an already-claimed external identity (`409 ACCOUNT_ALREADY_LINKED`), and prevents unlinking the last remaining login method (`400 LAST_LOGIN_METHOD`).
    - *Staging / Production Live OAuth Gate:* With `GITHUB_CLIENT_ID`/`SECRET` and `GOOGLE_CLIENT_ID`/`SECRET` configured, real OAuth login creates a unique `@handle` on first sign-in without implicitly merging accounts sharing an email (`accountLinking: { enabled: true, disableImplicitLinking: true, trustedProviders: ["github", "google"], allowDifferentEmails: true }`), while authenticated users can explicitly link a second provider via `/api/auth/link-social`.
12. **Personal Workflow E2E (`/me`):**
    - Progressive 2-stage capture creates both a private *From Work* take (multi-origin or single-origin) and a *From Reading* take via `prepareBean` → `saveBean`.
    - Filtering by decision domain (`tags`), origin kind, lifecycle state (`Active`, `In Tension`, `Superseded`, `Private`), and server-backed search works accurately.
    - Opening a take displays its `bean_revisions` timeline; resolving a `tensions_with` or creating a `supersedes` update increments `version` and updates lifecycle state; stale `expectedVersion` surfaces a non-destructive `409 VERSION_CONFLICT` recovery banner.
    - `/me?tab=insights` renders deterministic stats matching the user's created takes, revisions, tensions, Shelf count, and active AI grants; JSON and Markdown exports (`/api/export`) succeed.
13. **Sharing, Privacy, Live Shelf & Unseeded Onboarding E2E (`/`, `/sources`, `/sources/[id]`, `/@[handle]`, `/connect`):**
    - *Unseeded vs Seeded Home:* When 0 public takes exist (`COFFEE_CHAT_SEED_DEMO` unset), `/` renders the purposeful unseeded onboarding guide with working CTAs; when seeded or populated, `/` supports server-backed search and pagination across all public takes (not capped to 12 in-memory items).
    - *Redaction Gate & Axis Comparison:* Publishing a *From Work* take requires explicit redaction confirmation (`400 REDACTION_REQUIRED` if omitted). On `/sources/[id]`, visitors see the axis-by-axis comparison matrix (Quote/Anchor, Take, Trade-off, Boundary); a signed-in owner with a private take on that URL sees their private-stance banner while an incognito visitor sees zero trace of that private take (and `404` for private-only URLs).
    - *Live Shelf Hydration:* Saving/unsaving an author (`/@[handle]`) or take (`/sources/[id]`, `/`) hydrates `{ targetType, targetId, shelfItemId }` across full page reloads (passing `shelfItemId` cleanly to `DELETE /api/shelf`), displays `tradeoff` + `/sources/[id]` table link (via `firstSourceOriginId`) in `/me?tab=saved`, and vanishes immediately if the author unpublishes or deletes the target.
    - *Coffee Chat Dual-Label Copy & Jargon-Free Brew Handoffs:* Primary surfaces render signature Coffee Chat terms (**My Roastery**, **Bean**, **Roast**, **Brew**, **Tasting Notes**, **Shelf**, **Tables**, **Roast Log**) paired with their subtle plain-language sub-labels underneath via native Yogurt props; `/connect` reflects live active `oauth_grants` status when signed in; all copyable prompts on `/`, `/sources/[id]`, `/@[handle]`, `/me`, and `/connect` contain zero raw MCP function names (`list_beans`, `compare_perspectives`, `prepare_bean`, `scope=`); `/oauth/consent` approves and `/me?tab=settings` revokes a real OAuth grant.
    - *Interactive MCP App Bundles:* Playwright verifies rendering and interaction of `confirm-bean`, `bean-picker`, and `perspective-diff`.
14. **`@openboa/yogurt@0.2.0-local.1` & Accessibility Compliance:**
    - `npm run check:yogurt` passes with `0` errors reporting `Yogurt 0.2.0-local.1` across all 4 surfaces including **`apps/web/src/app`**.
    - Zero `.cc-*` custom layout classes remain in `packages/ui/src/styles.css`; zero nested `<Link><Button>` elements exist in rendered DOM; `NavHeader` does not use `AgentAvatar` as the Coffee Chat brand mark; `Yogurt` uses `material="neutral"`, obeys `0.2.0` monochrome + `#175174` `tone="brand"` CTA + zero-gradient/zero-static-shadow + `Badge dot={false}` count hygiene, and supports `appearance` (`auto` | `light` | `dark`) across desktop (`1440px`) and mobile (`390px`) viewports.
